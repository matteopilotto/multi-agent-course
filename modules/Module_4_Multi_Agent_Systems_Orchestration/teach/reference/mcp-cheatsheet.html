Roles

RoleIsAssignment 3
HostThe AI app; manages one client per serverPipeline process + ADK agent
ClientHolds one connection to one servertoolbox-core ToolboxClient
ServerServes tools/resources/prompts to clientsToolbox :5000 (/mcp)

Wire: JSON-RPC 2.0. Transports: stdio (local subprocess) · Streamable HTTP (POST + optional SSE). The 2026-07-28 revision is stateless: _meta on every request, server/discover, no initialize handshake. architecture · spec

Who talks to whom

The two tool messages

MethodCarriesFilled by
tools/list → resultname, description, inputSchema (+ optional title, outputSchema, annotations)Server (from tools.yaml)
tools/call → paramsname, argumentsThe model (“model-controlled”)
tools/call → resultcontent[], isErrorServer

The round trip: client lists → host gives schemas to the model → model emits a call → client sends tools/call → server runs it → host appends the result and calls the model again.

Errors

Protocol (unknown tool, malformed)JSON-RPC error, e.g. -32602
Execution (API, validation, business rule)result with "isError": true; shown to the model

Annotations are untrusted unless the server is trusted. tools spec

Toolbox tools.yaml (current flat format)

kind: source            # one YAML document per resource, separated by ---
name: my-pg-source
type: postgres
host: 127.0.0.1
port: 5432
database: toolbox_db
user: toolbox_user
password: ${PASSWORD}   # env var substitution
---
kind: tool
name: search-hotels-by-name
type: postgres-sql
source: my-pg-source
description: Search for hotels based on name.      # → model sees
parameters:                                         # → inputSchema
  - name: name
    type: string
    description: The name of the hotel.
statement: SELECT * FROM hotels WHERE name ILIKE '%' || $1 || '%';   # never leaves the server
---
kind: toolset
name: my_first_toolset
tools:
  - search-hotels-by-name

$1, $2… = parameters in order. Parameters default to required: true. README · postgres-sql

Enforced vs. stated

A rule is enforced where it holds even if the model is tricked or wrong (a lock), and only stated where it relies on the model obeying (a sign). Test: if the model misbehaved, would the rule still hold here?

RuleSignLock
Action type in the enum (M-7)Parameter descriptionCHECK constraint
Orders never mutated (M-6)PromptNo mutating tool + only GRANT SELECT
Only your own orders (M-4, M-5)“Only this user” in the promptWHERE … AND customer_email = $2 with the email bound by the host

Bound parameters: identity from the host, not the model

ToolboxClient → load_tool("get-order-status",
                          bound_params={"customer_email": session_email})   # value or callable

The host (which ran the login) supplies the value. The docs say bound values are “not requested or modified by the LLM”. Still to check: print the loaded tool's schema and confirm the bound parameter is missing from it. toolbox-core docs

Run and load

npx @toolbox-sdk/server --config tools.yaml     # MCP at http://127.0.0.1:5000/mcp
                                               # one toolset: /mcp/<toolset_name>
from toolbox_core import ToolboxClient
async with ToolboxClient("http://127.0.0.1:5000") as toolbox:   # speaks MCP by default
    tool  = await toolbox.load_tool("get_weather")
    tools = await toolbox.load_toolset("toolset_name")
    result = await tool(location="London")

toolbox-core docs (v1.4.0). --enable-api adds /api/tool/<name>/invoke (verified, v1.16.0). Lock it to local callers with --allowed-hosts 127.0.0.1,localhost.
